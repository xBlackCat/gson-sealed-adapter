# GSON Kotlin Sealed Class Adapter

Автоматическая сериализация и десериализация Kotlin sealed-классов и sealed-интерфейсов через Gson.

Плагин генерирует `TypeAdapterFactory` для каждого sealed-типа, помеченного аннотацией `@SealedAdapter`. Каждый подкласс сериализуется в JSON-контейнер с полем `type` (имя подкласса) и полем `data` (содержимое), что позволяет Gson корректно восстанавливать конкретный подтип при десериализации.

## Требования

- Kotlin **2.4+**
- Java **21+**
- Gson **2.14+** (подтягивается transitively через `sealed-adapter-api`)

## Подключение

Доступны два способа генерации фабрики — выберите один:

| Способ | Что нужно добавить |
|--------|--------------------|
| **KSP** | плагин `com.google.devtools.ksp` + `implementation("org.xblackcat.gson:sealed-adapter-api:0.1")` + `ksp("org.xblackcat.gson:sealed-adapter-ksp:0.1")` |
| **KCP** | плагин `org.xblackcat.gson.sealed-adapter` (зависимость `sealed-adapter-api` добавляется автоматически) |

Подробные инструкции — в разделах [KSP](#ksp) и [KCP](#kcp) ниже.

## Использование в коде

### Аннотация

Пометьте sealed-класс или sealed-интерфейс аннотацией `@SealedAdapter`:

```kotlin
import org.xblackcat.gson.adapter.SealedAdapter

@SealedAdapter
sealed interface Message {
    data class Text(val body: String) : Message
    data class Image(val url: String, val width: Int) : Message
    data object Ping : Message
}
```

### Регистрация фабрики в Gson

```kotlin
import com.google.gson.Gson
import com.google.gson.GsonBuilder
import org.xblackcat.gson.adapter.sealedClass

val gson: Gson = GsonBuilder()
    .registerTypeAdapterFactory(sealedClass<Message>())
    .create()
```

Или через extension-функцию:

```kotlin
val gson: Gson = GsonBuilder()
    .registerSealedAdapter<Message>()
    .create()
```

### Сериализация и десериализация

```kotlin
val message: Message = Message.Text("Hello, world!")

val json: String = gson.toJson(message, Message::class.java)
// {"type":"Text","data":{"body":"Hello, world!"}}

val restored: Message = gson.fromJson(json, Message::class.java)
// Message.Text(body="Hello, world!")
```

### Формат JSON

Каждый подкласс сериализуется в объект с двумя полями:

```json
{
  "type": "<имя подкласса>",
  "data": { ... поля подкласса ... }
}
```

Для `data object` поле `data` будет пустым объектом `{}`.

### Вложенные sealed-иерархии

Плагин рекурсивно собирает **все** подкласси, включая промежуточные sealed-классы. Имя подкласса в JSON — это путь от корня через точку:

```kotlin
@SealedAdapter
sealed interface Base {
    sealed interface Block : Base {
        data object One : Block
        data class Two(val a: Int, val b: String) : Block
    }
    sealed interface Code : Base {
        data object One : Code
        data class Two(val a: Int, val b: String) : Code
    }
}
```

| Экземпляр | JSON |
|-----------|------|
| `Base.Block.One` | `{"type":"Block.One","data":{}}` |
| `Base.Block.Two(1, "a")` | `{"type":"Block.Two","data":{"a":1,"b":"a"}}` |
| `Base.Code.One` | `{"type":"Code.One","data":{}}` |
| `Base.Code.Two(2, "b")` | `{"type":"Code.Two","data":{"a":2,"b":"b"}}` |

## KSP

Подключение через [Kotlin Symbol Processing](https://kotlinlang.org/docs/ksp-overview.html). Плагин генерирует `.kt`-файл с фабрикой во время компиляции.

### Настройка

**`settings.gradle.kts`:**

```kotlin
pluginManagement {
    repositories {
        mavenCentral()
        gradlePluginPortal()
    }
}

plugins {
    kotlin("jvm") version "2.4.21"
    id("com.google.devtools.ksp") version "2.3.9"
}
```

**`build.gradle.kts`** (модуль приложения):

```kotlin
plugins {
    kotlin("jvm")
    id("com.google.devtools.ksp")
}

dependencies {
    implementation("org.xblackcat.gson:sealed-adapter-api:0.1")
    ksp("org.xblackcat.gson:sealed-adapter-ksp:0.1")
}
```

### Что происходит при компиляции

1. KSP-процессор находит все классы с аннотацией `@SealedAdapter`.
2. Для каждого генерирует файл `<Имя>SealedTypeAdapterFactory.kt` в том же пакете.
3. Сгенерированный файл компилируется вместе с остальным кодом.

Пример сгенерированного кода для `Message`:

```kotlin
// Generated by sealed-adapter-ksp. Do not edit.
package com.example

import org.xblackcat.gson.adapter.ASealedTypeAdapterFactory

class MessageSealedTypeAdapterFactory : ASealedTypeAdapterFactory<Message>(
    Message::class,
    "Text" to Message.Text::class,
    "Image" to Message.Image::class,
    "Ping" to Message.Ping::class,
)
```

### Особенности

- Сгенерированные файлы попадают в `build/generated/ksp/` — их можно просмотреть, но не редактировать.
- При изменении sealed-иерархии KSP автоматически пересобирает фабрику.
- KSP работает с символами **текущего модуля** — sealed-класс и его подкласси должны быть в том же модуле, где подключён KSP.

## KCP

Подключение через [Kotlin Compiler Plugin](https://kotlinlang.org/docs/compiler-plugins.html). Плагин генерирует IR-класс напрямую во время компиляции — промежуточные файлы не создаются.

### Настройка

**`settings.gradle.kts`:**

```kotlin
pluginManagement {
    repositories {
        mavenCentral()
        gradlePluginPortal()
    }
}

plugins {
    kotlin("jvm") version "2.4.21"
    id("org.xblackcat.gson.sealed-adapter") version "0.1"
}
```

**`build.gradle.kts`** (модуль приложения):

```kotlin
plugins {
    kotlin("jvm")
    id("org.xblackcat.gson.sealed-adapter")
}
```

> Плагин `org.xblackcat.gson.sealed-adapter` автоматически:
> - добавляет свой артефакт на classpath компилятора;
> - добавляет зависимость `org.xblackcat.gson:sealed-adapter-api` (той же версии) в `implementation`.
>
> Отдельные зависимости `ksp(...)`, `annotationProcessor(...)` или `implementation("...sealed-adapter-api...")` не нужны.

### Что происходит при компиляции

1. FIR-расширение валидирует аннотацию (sealed, не inner, не local).
2. IR-расширение находит все классы с `@SealedAdapter` и генерирует `IrClass` фабрики.
3. Сгенерированный класс добавляется в IR-модуль и компилируется в bytecode.

Результат в bytecode идентичен KSP-подходу — класс `<Имя>SealedTypeAdapterFactory` с тем же конструктором.

### Особенности

- Файлы не генерируются — фабрика существует только в bytecode.
- Валидация аннотации происходит на этапе FIR: неправильное применение (`@SealedAdapter` на non-sealed, inner, local) выдаёт ошибку компиляции.
- KCP работает с символами **текущего модуля** — sealed-класс и его подкласси должны быть в том же модуле, где подключён плагин.

## Сравнение подходов

| Критерий | KSP | KCP |
|----------|-----|-----|
| Механизм | Генерация `.kt`-файлов → компиляция | Генерация IR → bytecode |
| Промежуточные файлы | Да (`build/generated/ksp/`) | Нет |
| Валидация аннотации | Warning в логе KSP | Ошибка компиляции (FIR) |
| Настройка | `ksp(...)` + `implementation(...api...)` | `id("org.xblackcat.gson.sealed-adapter")` (API добавляется автоматически) |
| Результат в bytecode | Идентичен | Идентичен |
| Формат JSON | Идентичен | Идентичен |
| Требования | KSP 2.3.9+ | Kotlin 2.4+ (K2) |
